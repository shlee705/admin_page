기준일: 2026-10-12 (Asia/Seoul). [관리 가이드·ID 대장](bugs.md)

## 유형 설명과 작성 규칙

잘못된 목적지, URL만 변경되고 화면 유지, 뒤로 가기 오류, 새로고침 경로 복원 실패, 잘못된 redirect를 다룬다. 현재 사이트는 HTML 문서 이동 방식이며 SPA router를 전제하지 않는다.

공통 기본 정보·10개 절을 빠짐없이 작성한다. 미확정 항목은 미확정으로, 적용되지 않는 항목은 근거와 함께 해당 없음으로 쓴다. 구현 전 계획/예상과 실제 검증을 구분한다. 예시는 모두 미구현이며 현재 정답 집합에 포함되지 않는다.

유형별 추가 확인 항목: 시작 URL, 사용자 동작, 기대 목적지, 실제 목적지, URL 변경 여부, 브라우저 History 상태, 새로고침 및 뒤로 가기 결과.

### 8. 탐지 방법

최종 URL·DOM의 페이지 식별·활성 메뉴를 상태 비교한다. 예상 URL과의 규칙 비교가 가능하고 redirect chain/History는 네트워크와 브라우저 동작으로 확인한다. HTTP 200만으로 정상 이동을 판정하지 않는다.

### 9. 검증 기준

Baseline에서는 결함이 없어야 한다. 주입 버전에서는 위 절차로 재현되어야 한다. 의도하지 않은 추가 결함과 다른 기능의 불필요한 영향이 없어야 한다. 같은 초기 데이터·계정·환경에서 비교한다. 다른 메뉴와 직접 calendar.html 접근은 정상이어야 한다. 공통 NAV 소비자의 영향도 검사한다.

### 10. 검증 결과

미실행 — 미구현. 실제 URL/History 검증 결과·커밋 없음.

## N2: Calendar 메뉴가 Chat 화면을 엶

### 기본 정보

| 항목 | 값 |
|---|---|
| Bug ID | N2 |
| 제목 | Calendar 메뉴가 Chat 화면을 엶 |
| 유형 | routing |
| 증상 분류 | wrong_target |
| 구현 상태 | 구현됨 |
| 대상 기능 | 공통 Sidebar / Calendar |
| 발생 위치 | 공통 Shell 의 Calendar 메뉴 (같은 메뉴 정의를 쓰는 명령 팔레트 포함) |
| 수정 파일 | `src/assets/scripts/2026/Shell.js`, `dist/` |
| 과거 프로젝트 ID | 없음 |

### 1. 버그 개요

사이드바의 Calendar 메뉴가 Chat 화면을 연다. 위 **N1 작성 예시의 시나리오를 실제로
구현한 것**이다. N1 은 예시라 정답 집합에 들어가지 않으므로 새 번호로 등록했다.

### 2. 정상 기대 동작 (Expected Behavior)

Calendar 를 누르면 `calendar.html` 의 달력(제목 예: `October 2026`)이 열리고, 사이드바에서
Calendar 가 현재 위치로 강조된다.

### 3. 결함 동작 (Actual Defective Behavior)

같은 클릭이 `chat.html` 을 열어 제목 `Chat — team` 이 보이고, 사이드바에서 Chat 이
강조된다. 이동 자체는 정상적으로 일어나고 오류가 없다.

### 4. 재현 조건 (Preconditions)

alice 로 로그인. 데이터와 무관하다.

### 5. 재현 절차 (Steps to Reproduce)

1. 로그인 후 첫 화면에서 왼쪽 사이드바를 본다.
2. **Calendar** 를 누른다.
3. 도착 화면의 제목과 사이드바에서 강조된 메뉴를 확인한다.

### 6. 예상 관찰 결과

| | Baseline | 주입 |
|---|---|---|
| 도착 주소 | `calendar.html` | `chat.html` |
| 제목 | `October 2026` | `Chat — team` |
| 강조된 메뉴 | Calendar | Chat |

### 7. 버그 구현 방법

`Shell.js` 의 `NAV` 에서 `calendar` 항목의 `href` 를 `calendar.html` 에서 `chat.html` 로
바꿨다. 명령 팔레트도 같은 `NAV` 를 읽으므로 함께 바뀐다.

### 8. 탐지 방법

**규칙 (실측, Baseline 오탐 0).** 둘 다 잡혔다.
- 메뉴를 누른 뒤 사이드바의 현재 위치(`is-active`) 메뉴가 누른 메뉴와 같아야 한다.
- 사이드바에서 서로 다른 메뉴가 같은 목적지를 가리키면 안 된다 (Calendar·Chat → `chat.html`).

**실패한 규칙.** "메뉴 글자와 도착 화면 제목이 단어 하나라도 겹쳐야 한다" 는 Baseline
에서도 3건이 걸렸다 (Home → `Welcome, Alice`, Calendar → `October 2026`, Email →
`Inbox · …`). 메뉴 글자와 화면 제목은 원래 다르게 쓰이는 경우가 많다.

**AI.** 메뉴 글자(Calendar)와 도착 화면의 내용(채팅)이 뜻으로 맞지 않는 것을 판단한다.

### 9. 검증 기준

Baseline에서는 결함이 없어야 한다. 주입 버전에서는 위 절차로 재현되어야 한다. 의도하지 않은 추가 결함과 다른 기능의 불필요한 영향이 없어야 한다. 같은 초기 데이터·계정·환경에서 비교한다.

### 10. 검증 결과

2026-10-16, Baseline `main`(`ccd7fcf`) / 주입 `routing`, 위 측정 조건. 6절 표대로 재현됐다.
Baseline 에서는 재현되지 않았다. **통과.**

### 유형별 추가 확인

| 항목 | 값 |
|---|---|
| 시작 URL | `index.html` |
| 사용자 동작 | Sidebar 의 Calendar 클릭 |
| 기대 목적지 | `calendar.html` / 달력 |
| 실제 목적지 | `chat.html` / `Chat — team` |
| URL 변경 여부 | 변경됨 |

| 새로고침 및 뒤로 가기 결과 | 새로고침해도 `chat.html` 유지. 뒤로 가기는 정상 |

### 4. 재현 조건 (Preconditions)
