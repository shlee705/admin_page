# UI 버그 명세

기준일: 2026-10-12 (Asia/Seoul). [관리 가이드·ID 대장](bugs.md)

## 유형 설명과 작성 규칙

텍스트/요소 겹침, 화면 밖 넘침, 잘못된 표시·강조, 모달/드롭다운 오류, 반응형 레이아웃 깨짐을 다룬다. viewport·브라우저·배율·테마·데이터를 고정하고 미적 선호와 재현 가능한 결함을 구분한다.

공통 기본 정보·10개 절을 빠짐없이 작성한다. 미확정 항목은 미확정으로, 적용되지 않는 항목은 근거와 함께 해당 없음으로 쓴다. 구현 전 계획/예상과 실제 검증을 구분한다. 예시는 모두 미구현이며 현재 정답 집합에 포함되지 않는다.

유형별 추가 확인 항목: 화면 크기, 브라우저 환경, 영향을 받는 UI 요소, 정상 레이아웃, 결함 발생 시 레이아웃, 시각적 탐지 가능성, 기능적 영향 여부.

현재 기능을 사용한 작성 예시이며 후보 파일과 정상 계약은 향후 구현 전 확인한다.

## U1: 모바일 Email 요소 넘침

### 기본 정보

| 항목 | 값 |
|---|---|
| Bug ID | U1 |
| 제목 | 모바일 Email 요소 넘침 |
| 유형 | ui |
| 증상 분류 | visual |
| 구현 상태 | 미구현 |
| 대상 기능 | Email |
| 발생 위치 | email.html의 메일 목록 영역 |
| 수정 파일 | 없음 — 실제 코드 변경 전 |
| 과거 프로젝트 ID | 없음 |

### 1. 버그 개요

모바일에서 메일 목록 최소 너비가 화면보다 커져 수평 넘침이 발생하는 작성 예시다.

### 2. 정상 기대 동작 (Expected Behavior)

모바일 레이아웃에서 목록과 조작 요소가 화면 안에 표시되어 정상 접근 가능하다.

### 3. 결함 동작 (Actual Defective Behavior)

메일 목록이 viewport 밖으로 넘쳐 일부 요소가 잘리거나 수평 스크롤이 생긴다.

### 4. 재현 조건 (Preconditions)

로그인 테스트 계정, 동일한 Inbox fixture, 390×844 CSS px, 배율 100%, light theme. 브라우저 종류/버전·DPR은 검증 시 고정·기록한다.

### 5. 재현 절차 (Steps to Reproduce)

1. 조건을 고정하고 email.html의 Inbox를 연다.
2. 메일 목록 오른쪽 요소와 문서 수평 스크롤을 확인한다.
3. 화면·요소 경계를 캡처한다.
4. 같은 fixture로 Baseline 및 desktop 1440×900과 비교한다.

### 6. 예상 관찰 결과

예상: 주입 모바일에서 목록 경계가 viewport를 벗어나고 scrollWidth가 clientWidth보다 커진다. 실제 치수·스크린샷은 구현 후 기록한다.

### 7. 버그 구현 방법

계획: src/assets/styles/2026/_email.scss 및 _responsive.scss에서 실제 목록 선택자·media 규칙을 확인한 뒤 모바일 목록에만 과도한 최소 너비를 직접 적용한다. 버그 상태에 따른 CSS 분기 없음. 현재 변경 없음.

### 8. 탐지 방법

DOM bounding box/scrollWidth의 규칙 검사와 고정 환경 화면 비교. 의도된 내부 스크롤과 문서 넘침을 구별해야 하며 잘림·조작 불가능 여부는 시나리오 및 의미적 판단이 필요하다. Console 오류를 필수 증상으로 삼지 않는다.

### 9. 검증 기준

Baseline에서는 결함이 없어야 한다. 주입 버전에서는 위 절차로 재현되어야 한다. 의도하지 않은 추가 결함과 다른 기능의 불필요한 영향이 없어야 한다. 같은 초기 데이터·계정·환경에서 비교한다. desktop, 메일 읽기/발신/필터와 타 페이지 레이아웃 영향을 확인한다.

### 10. 검증 결과

미실행 — 미구현. 화면 캡처·치수·검증 커밋 없음.
