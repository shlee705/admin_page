# 기능적 버그 명세

기준일: 2026-10-12 (Asia/Seoul). [관리 가이드·ID 대장](bugs.md)

## 유형 설명과 작성 규칙

버튼 무반응, 중복 제출, 수정 후 일부 상태 미갱신, 성공 메시지와 실제 결과 불일치, 일부 동작 누락을 다룬다. HTTP 성공만으로 기능 성공을 판정하지 않고 저장·재조회·UI를 함께 비교한다.

공통 기본 정보·10개 절을 빠짐없이 작성한다. 미확정 항목은 미확정으로, 적용되지 않는 항목은 근거와 함께 해당 없음으로 쓴다. 구현 전 계획/예상과 실제 검증을 구분한다. 예시는 모두 미구현이며 현재 정답 집합에 포함되지 않는다.

유형별 추가 확인 항목: 사용자 동작, 서버 처리 여부, 데이터 변경 여부, UI와 실제 상태의 일치 여부, 중복 실행 가능성.

## 명세 예시의 적용 범위

현재 기능을 사용한 작성 예시이며 후보 파일과 정상 계약은 향후 구현 전 확인한다.

## F1: 일정 저장 버튼 무반응

### 기본 정보

| 항목 | 값 |
|---|---|
| Bug ID | F1 |
| 제목 | 일정 저장 버튼 무반응 |
| 유형 | functional |
| 증상 분류 | no_response |
| 구현 상태 | 미구현 |
| 대상 기능 | Calendar |
| 발생 위치 | calendar.html의 일정 생성 모달 |
| 수정 파일 | 없음 — 실제 코드 변경 전 |
| 과거 프로젝트 ID | 없음 |

### 1. 버그 개요

일정 생성 모달에서 Save를 눌러도 요청과 상태 변화가 없는 결함의 작성 예시다.

### 2. 정상 기대 동작 (Expected Behavior)

유효한 새 일정 저장 시 한 번 생성되어 목록/달력에 나타나고 재조회에도 남는다.

### 3. 결함 동작 (Actual Defective Behavior)

Save 후 생성 요청이 없고 모달과 일정 목록이 그대로 남는다.

### 4. 재현 조건 (Preconditions)

로그인한 테스트 계정, 격리 DB, calendar.html 접근, 비어 있는 테스트 시간 구간. 유효한 제목·시작/종료·시간대를 입력한다.

### 5. 재현 절차 (Steps to Reproduce)

1. calendar.html을 열고 새 일정 모달을 연다.
2. 제목 BUG-F1, 겹치지 않는 유효한 미래 시작/종료 시간을 입력한다.
3. Save를 한 번 누르고 UI와 네트워크를 관찰한다.
4. 모달을 닫고 재조회하여 같은 제목 일정이 생성되지 않았는지 확인한다.

### 6. 예상 관찰 결과

Baseline은 생성 및 목록 갱신, 주입 버전은 생성 요청/저장/갱신 모두 없음. 대기 시간은 정상 응답 시간과 비교하여 구현 전 고정한다.

### 7. 버그 구현 방법

계획: src/assets/scripts/2026/calendar.js의 정상 생성 핸들러를 확인하고 해당 모달의 저장만 조기에 반환하도록 최소 변경한다. 다른 일정 편집·삭제·조회까지 막지 않는다. 현재 변경 없음.

### 8. 탐지 방법

네트워크 요청 없음과 DOM/UI 상태 불변을 비교한다. no_state_change 규칙은 정상 지연·입력 오류와 구별할 기준 시간이 필요하다. 재조회/저장 상태 비교로 무반응을 확인하고 HTTP 오류/Console 예외가 필수로 발생한다고 가정하지 않는다.

### 9. 검증 기준

Baseline에서는 결함이 없어야 한다. 주입 버전에서는 위 절차로 재현되어야 한다. 의도하지 않은 추가 결함과 다른 기능의 불필요한 영향이 없어야 한다. 같은 초기 데이터·계정·환경에서 비교한다. 일정 편집·삭제·조회와 입력 검증은 정상이어야 한다.

### 10. 검증 결과

미실행 — 미구현. 구현 커밋·일자·테스트·증거 없음.
